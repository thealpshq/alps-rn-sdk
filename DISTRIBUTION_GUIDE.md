# Distribution Guide - How Users Get the SDK

This guide explains how the Alps React Native Widget SDK is packaged, published, and distributed to end users.

## Overview

The SDK is distributed via **npm** (Node Package Manager) as a public package named `@tryalps/rn-widget`.

Users can install it like any other npm package:

```bash
npm install @tryalps/rn-widget
```

## How It Works

### 1. Source Code Structure

**What's Published:**
- `/src` - TypeScript source code (all screens, components, state, API)
- `/dist` - Compiled JavaScript (generated by build process)
- `/dist/*.d.ts` - TypeScript declaration files for IDE autocomplete
- `README.md`, `INTEGRATION_GUIDE.md`, `QUICKSTART.md` - Documentation
- `package.json` - Metadata and dependencies

**What's NOT Published:**
- `App.tsx` (test app)
- `.git`, `.github` (version control)
- `examples/` (development examples, users see on GitHub)
- `node_modules/` (installed separately)
- Build cache, test files, etc.

See `.npmignore` for exact exclusions.

### 2. Build Process

**Before Publishing:**

```bash
# 1. Compile TypeScript to JavaScript
npm run build

# 2. This generates:
#    - dist/index.js (main entry point)
#    - dist/ui/*.js (compiled components)
#    - dist/**.d.ts (TypeScript types)
```

**What `npm run build` does:**
1. Runs TypeScript compiler (`tsc`)
2. Generates CommonJS output in `/dist`
3. Creates declaration files (`.d.ts`) for type checking
4. Source maps generated for debugging

### 3. Package Metadata

**In `package.json`:**

```json
{
  "name": "@tryalps/rn-widget",          // npm package name
  "version": "0.1.0",                    // semver version
  "main": "dist/index.js",               // entry point
  "types": "dist/index.d.ts",            // TypeScript types
  "peerDependencies": {                  // what user must install
    "react": "^18.0.0",
    "react-native": "^0.68.0"
  },
  "dependencies": {                      // what we install
    "zustand": "^4.4.0",
    "pusher-js": "^8.3.0",
    "@react-native-async-storage/async-storage": "^1.23.0"
  }
}
```

**Why peer dependencies?**
- `react` and `react-native` are huge packages
- Users likely already have them installed
- We don't want two copies in `node_modules`
- npm will warn if user doesn't have them

### 4. Publishing to npm

**Step-by-step:**

```bash
# 1. Make sure everything is built
npm run build

# 2. Log in to npm (one-time setup)
npm login
# Enter username, password, email, OTP

# 3. Publish
npm publish --access public
# (--access public because @tryalps is a scope)

# 4. Done! Package is now on npm registry
```

**Verification:**
- Visit https://www.npmjs.com/package/@tryalps/rn-widget
- Users can now install it

### 5. Versioning

We follow **semantic versioning** (semver):

```
MAJOR.MINOR.PATCH
  0 .  1  .  0

- MAJOR (0): Breaking changes
- MINOR (1): New features, backwards compatible
- PATCH (0): Bug fixes, backwards compatible
```

**Examples:**
- `0.1.0` → `0.2.0`: Added new screen (new feature)
- `0.1.0` → `0.1.1`: Fixed bug (patch)
- `0.1.0` → `1.0.0`: Redesigned API (breaking change)

**Update process:**
```bash
# Bump version in package.json
{
  "version": "0.1.1"  // was 0.1.0
}

# Build and publish
npm run build
npm publish
```

### 6. Installation Flow (User Perspective)

When a user runs `npm install @tryalps/rn-widget`:

1. **npm registry lookup** - npm checks registry.npmjs.org for `@tryalps/rn-widget`
2. **Download package** - npm downloads latest version as a `.tar.gz` file
3. **Extract to node_modules** - Files are extracted to `node_modules/@tryalps/rn-widget/`
4. **Install dependencies** - npm runs `npm install` for packages in `dependencies`
5. **Peer deps check** - npm warns if `react` or `react-native` missing
6. **Done** - Package is ready to `import` in user code

### 7. File Layout After Installation

```
user-app/
├── node_modules/
│   └── @tryalps/
│       └── rn-widget/                  ← Installed here
│           ├── dist/                   ← Compiled JS + types
│           │   ├── index.js
│           │   ├── index.d.ts
│           │   ├── ui/
│           │   ├── api/
│           │   └── ... (all compiled files)
│           ├── package.json
│           ├── README.md
│           ├── INTEGRATION_GUIDE.md
│           └── ... (documentation files)
│   ├── react-native/
│   ├── zustand/
│   ├── pusher-js/
│   └── (2000+ other packages)
└── src/
    └── App.tsx                         ← User's code
        import { AlpsWidget } from '@tryalps/rn-widget'
```

### 8. How Users Import the SDK

In user code:

```tsx
// User writes this:
import { AlpsWidget, createAlpsConfig } from '@tryalps/rn-widget'

// npm resolves to:
// node_modules/@tryalps/rn-widget/dist/index.js

// Which exports:
// export { AlpsWidget } from './ui/AlpsWidget'
// export { createAlpsConfig } from './config/AlpsConfig'
// (etc. - see src/index.ts for full exports)
```

### 9. TypeScript Support

**Declaration files** (`.d.ts`) are automatically generated during build:

```bash
npm run build  # generates dist/**/*.d.ts
```

Users get IDE autocomplete automatically:

```tsx
import { AlpsWidget } from '@tryalps/rn-widget'
// IDE knows:
// - AlpsWidget is a React component
// - Config type: { widgetKey: string, visitorName?: string, ... }
// - Available props and their types
```

### 10. Updates & Versions

**Check latest version:**
```bash
npm view @tryalps/rn-widget
```

**Upgrade to latest:**
```bash
npm update @tryalps/rn-widget
```

**Lock to specific version:**
```json
{
  "dependencies": {
    "@tryalps/rn-widget": "0.1.5"
  }
}
```

## Distribution Channels

### 1. npm (Primary)

**How:** Package on public npm registry
**URL:** https://www.npmjs.com/package/@tryalps/rn-widget
**Installation:** `npm install @tryalps/rn-widget`

### 2. Yarn (Automatic)

**How:** Automatically mirrors npm
**Installation:** `yarn add @tryalps/rn-widget`

### 3. GitHub (Source)

**How:** Clone from GitHub repository
**Installation:** `npm install tryalps/rn-widget`
**Use case:** Bleeding edge, development versions

### 4. Private npm Registry (Optional)

**How:** Host on private npm server (Verdaccio, etc.)
**Installation:** `npm install @tryalps/rn-widget --registry https://private.npm.local`
**Use case:** Enterprise customers, internal packages

## CI/CD Pipeline

**Automated publishing workflow:**

```yaml
# .github/workflows/publish.yml
on:
  release:
    types: [created]

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: 16
          registry-url: 'https://registry.npmjs.org'
      - run: npm ci
      - run: npm run build
      - run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

This automates publishing every time a GitHub release is created.

## File Sizes

**Typical package size:**
- Uncompressed: ~200 KB (source + dist)
- npm tarball: ~50 KB (gzipped)
- After install: ~500 KB (with deps)

**Breakdown:**
```
- Compiled JS: ~80 KB
- TypeScript types: ~40 KB
- Dependencies (zustand, pusher-js): ~250 KB
- node_modules overhead: ~130 KB
```

## Security & Integrity

**Protection mechanisms:**

1. **npm signed packages** - npm verifies package integrity
2. **Package lock files** - Users have `package-lock.json` for reproducible installs
3. **GitHub releases** - Source code tagged and verified on GitHub
4. **Code signing** (optional) - Contributors sign commits

**Dependency security:**
```bash
# Check for known vulnerabilities
npm audit

# Fix vulnerabilities
npm audit fix
```
